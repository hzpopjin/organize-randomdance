# 校验与交付

## 技术 QA

逐项记录并检查：
- 实际格式／codec、声道、采样率、时长及完整解码结果。
- 片段是否包含需求中的完整连续段落，起止是否符合上退场与源曲边界。
- 峰值与真峰值是否存在溢出风险，是否重编码及调整增益。
- 输出 basename、Custom 中文备注、文件数量、大小与 SHA-256。

技术解码和波形／ASR 检查不是实际听审。没有真实播放听审时如实说明；不可宣称“耳听无爆音”“全部试听通过”。文件名含 HiRes 或高采样率不证明无损来源，MP3 不能描述为无损输出。

## 附件与 ZIP

交付前重新确认本次最终版本，剔除旧版和错误附件。音频 ZIP 根目录只放本次所需 MP3，保留约定文件名，不放报告、表格、脚本、父文件夹或旧版本。质量报告如需交付，独立提供。

使用当前 Library 流程上传与回取校验；记录返回的正式文件标识，回取文件检查大小与 SHA-256，不将本地生成完成或上传请求成功混同用户已能下载正确版本。

## 保存到用户电脑

先检查当前获授权的目标目录、现有命名和同名文件。只有本次指令明确允许相应写入时才执行；历史示例目录不能当作未来默认保存位置。

Library 下载或元数据登记失败时保留阻塞状态，不绕过元数据 helper，也不通过伪造成功响应、跳过安全标记或静默改目标实现“成功”。Windows 下载流程若出现 os.setxattr／download failed 等错误，区分：用户已收到附件、电脑下载失败、本地保存未验证。只报告真实达到的状态。

源文件与目标电脑实际文件的 SHA-256 一致，且路径和数量正确后，才能说“已保存”。有附件而未完成本地验证时应说附件已交付、自动保存仍未完成；不能因目标文件名存在就宣称同步成功。
